# 大纲编辑器章节删除入口设计

## 目标

在大纲编辑器的章节标题右侧新增一个可见的“删除”按钮，让用户无需切换到写作页侧边栏即可删除当前正在编辑大纲的章节。

## 范围

- 仅改动大纲页的章节标题区域、确认交互和对应的回归测试。
- 复用现有 `useChapterStore.deleteChapter`，不新增 API、数据库字段或翻译键。
- 删除仍是不可恢复操作，必须经过二次确认。

## 交互与状态

1. 当大纲页有选中章节时，在编辑区标题行右侧显示带 `Trash2` 图标的“删除”按钮；无选中章节时不显示。
2. 点击按钮只打开确认对话框，不立即发起删除请求。对话框沿用侧边栏现有的标题、不可恢复提示、取消、失败提示与删除中禁用状态。
3. 确认后调用 `deleteChapter(project, { id, volumeId, num })`。调用者保存当前项目名和项目实例 ID，若项目在确认期间切换则关闭对话框且不执行删除。
4. 删除成功后通知章节、角色、记忆与统计数据刷新；大纲页将选中项切换到被删章节之后的章节，若不存在则切换到之前的章节；仅有一章时显示空态。
5. 删除失败时保留对话框、当前选中章节和编辑草稿，并显示错误。

## 实现边界

`Outline.tsx` 只负责大纲页自身的选中状态和按钮/对话框展示；章节精确定位删除、草稿丢弃、卷列表刷新以及写作页当前章节回退继续由 `useChapterStore.deleteChapter` 负责。这样不会引入第二套数据删除逻辑。

## 测试与验收

- 先补一条失败的纯逻辑回归测试：删除大纲页选中章节时，选择顺序为下一章、否则上一章、仅一章则为空。
- 保留既有章节删除契约测试，确保请求仍包含章节 ID 与分卷 ID，并且失败不清理草稿。
- 手工验收：在大纲页删除中间章节和最后一章；取消时不删除；确认后刷新页面，章节不再出现。

## 验收标准

- 截图红框对应位置出现“删除”按钮。
- 按钮不会绕过确认对话框。
- 删除后大纲页保持在相邻章节，而不是跳回第一章。
- 删除失败不会丢失当前大纲编辑内容。
