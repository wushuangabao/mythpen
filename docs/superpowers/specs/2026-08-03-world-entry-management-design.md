# 世界观条目管理设计

## 目标

让作者能够在“世界观设定”页完整管理任一条目，并让页面、REST API 与 AI 工具调用共享同一套字段和标签契约。

## 用户交互

- 世界观卡片保留浏览用途，并提供明确、可键盘访问的“编辑”入口。
- 编辑对话框预填分类、名称、描述和标签；保存后刷新列表并广播 `world` 数据变更。
- 标签以逗号输入和展示，保存为 JSON 字符串数组；旧的 JSON 字符串和旧的逗号字符串均可读取。
- “删除”只在编辑对话框内提供；点击后打开二次确认对话框。删除失败保留确认对话框并显示错误，成功后关闭两个对话框并刷新列表。
- 将已存在但此前未在新建/筛选中公开的 `technology` 分类纳入界面选项。

## 数据与 AI 契约

- `world_entries.tags` 继续使用现有 `TEXT` 列，不做数据库迁移。
- 后端新增纯标签归一化模块。REST 创建/更新与 AI 工具创建/更新都将字符串、旧 JSON 字符串或字符串数组归一化为 JSON 字符串数组。
- AI 工具 `create_world_entry`、`update_world_entry` 的参数模式将 `tags` 声明为字符串数组，并列出 `technology`；执行器仍接受旧字符串调用以保持兼容。
- `list_world` 返回给 AI 的 `tags` 为字符串数组，便于模型读取并在后续 `update_world_entry` 中原样提交。
- `delete_world_entry` 保持 ID 定位和不可逆提示；新增回归测试证明它与更新工具操作同一条数据。

## 实现边界

- 不引入新的 UI 测试框架或依赖。现有仓库没有 DOM 测试运行器；页面交互通过人工验收，纯数据/API 契约通过 Node 原生测试覆盖。
- 不改动项目既有的 AI 工具循环、数据库结构或无关页面。

## 验收标准

1. 用户能编辑并持久化四个字段，且已有 `technology` 条目不会丢失分类。
2. 标签从旧 JSON/逗号格式可读，保存后为去空白、去重的 JSON 数组。
3. 删除必须确认；网络错误时界面不丢失上下文。
4. REST 与 AI 工具均可创建、更新、列出和删除同一世界观条目。
